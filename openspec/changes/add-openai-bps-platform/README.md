# 变更提案：OpenAI BPS 平台

> **状态：阶段 0–6、8、9 已实现（文本 + 工具桥 + 压缩 + 结构化 + 目录 + 管理端）；阶段 7（计费/错误分类）、10（真实账号验收）待做**。实现提交见 `git log --grep openai-bps`。

## 一句话

新增独立平台 `openai_bps`，接入 ChatGPT Excel/BPS 权益账号的 Responses 上游，提供文本、工具隧道、压缩与结构化输出四条链路，默认关闭、可整体回滚。

## 为什么单独立项

- 上游地址/鉴权/协议能力与既有 OpenAI 两条链路都不同，混在一个平台里会把风险扩散到全部 OpenAI 流量。
- 协议非公开契约，需要冻结参考实现并保留平台级 kill switch。
- 状态层（工具 item、压缩摘要、会话绑定）强依赖 Redis，需要独立验收。
- 参考实现 sub4api 已闭源停更，只能移植协议事实，不能当作可跟踪的上游。

## 前置条件

1. **真实 BPS 账号**（Access Token）：没有它只能完成模拟上游测试，无法验收。
2. **Redis**：该平台的会话/工具/压缩状态强依赖，不做进程内降级。
3. **迁移窗口**：平台枚举扩展迁移需要在目标环境执行（纯加性）。
4. **合规确认**：BPS 权益账号用于中转可能违反上游条款，需运营/法务确认后再开启。

## 建议实施顺序

1. 阶段 0（参考冻结 + 真实账号探针）——必须先做，决定协议细节是否与冻结版本一致。
2. 阶段 1–3（平台注册、凭证、文本网关）——最小可用闭环。
3. 阶段 4–6（工具桥、压缩、结构化）——Codex 工具链完整体验。
4. 阶段 7–9（计费错误、目录、管理端）——可运营、可排障。
5. 阶段 10（灰度与回滚演练）——默认关闭，按分组灰度。

## 风险提示

- 上游协议随时可能变化；平台级开关是唯一快速止损手段。
- 账号存在封禁风险，UI 与文档必须强提示。
- 工具隧道与压缩链路长，任何静默失败都会表现为「工具不执行/上下文丢失」，验收必须覆盖异常路径。
