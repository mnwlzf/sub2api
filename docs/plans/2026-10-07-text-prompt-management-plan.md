# sub2api 文本提示词管理实施计划

日期：2026-10-07
状态：待实施；本次仅交付设计与计划。
依据：[详细设计](2026-10-07-text-prompt-management-design.md)。

## 1. 交付边界与顺序

按 M0 → M1 → M2 → M3 → M4 → M5 → M6 顺序推进。M4 的管理页面可以在 M2 API 契约稳定后独立开发；本计划不启动多代理或后台实施任务。

完整第一阶段包含：模板/版本后台、分组绑定与关系级覆盖、经验证的 Chat/Responses 文本适配、结构预览、管理员显式 A/B、请求记录与回滚。任何阶段完成均不得单独宣称全功能已完成。

不包含图片、自动搜集或优化提示词、拒答自动换词、生产流量双发、会话级版本固定和所有第三方协议兼容。

## 2. M0：代码路径核实与契约冻结

工作：

1. 读取仓库开发约定，记录当前 commit、工作树状态和新增迁移编号。
2. 跟踪 Chat→Chat、Chat→Responses、Responses→Responses、Responses→Chat 四条路径。
3. 标记模型映射、兼容性修改、最后一次 instructions/messages 修改、签名、缓存键、发送与日志调用位置。
4. 跟踪账号重试、复合分组和 fallback 的权限与有效分组解析。
5. 列出现有 OAuth/Claude/MCP 提示词改写点，建立不支持路径清单。
6. 明确请求上下文携带冻结策略的方法；避免把业务配置写入上游私有字段。
7. 冻结 DTO、错误码、profile ID、审计字段与模型精确匹配规则。

产物：路径证据表、API 契约和脱敏请求 fixtures。每条路径明确原始 body、转换后 body、最终 body 的边界。

验收：能指出每条支持路径的唯一注入位置和签名顺序；未核实的路径不能标记支持。若现有结构无法保证注入后无修改，先将该路径拆成明确的最终化步骤，再接入模板。

## 3. M1：持久化和版本服务

拟修改范围：backend/ent/schema、backend/migrations、backend/internal/repository、backend/internal/service，以及 Ent 生成产物。

任务：

- 新增模板、草稿、不可变版本、分组绑定、账号分组覆盖、评估与审计数据结构。
- 使用外键、CHECK、唯一索引保证 mode/version 配套和关系存在。
- 发布版本禁止 UPDATE/DELETE；元数据、草稿和绑定使用乐观锁。
- 实现发布事务、版本号分配、幂等键、发布内容哈希与 manifest 哈希。
- 配置变更与管理审计同事务，分组策略 generation 同步增加。
- 新迁移遵循向前、不可修改历史迁移的约定。

测试：全新数据库、已有数据库增量迁移、约束错误、并发发布、重复提交、版本不可修改、分组成员移除、归档仍保留既有绑定。

验收：并发更新不会丢失数据；发布得到可重复核验的固定快照；原有分组默认关闭。Ent 生成结果与 schema 一致。

回滚：功能尚未启用，保留增量表；程序可回到旧版本，不执行删表回滚。

## 4. M2：管理 API 与结构预览

拟修改范围：管理员 handler、DTO、路由注册、service 注入和 API 契约测试。

任务：

- 实现模板列表/元数据、草稿读写、发布与版本查询。
- 实现分组绑定和分组内账号覆盖；不增加账号全局覆盖。
- 实现 expected_revision 冲突处理与管理员权限校验。
- 实现绑定前兼容性预检，返回可用账号数及排除原因。
- 实现 preview：给定脱敏样本、固定版本和 profile，返回结构差异、摘要和新增字节数，不调用上游。
- 分组复制显式禁用新组绑定；删除/移除关系时清理运行配置并保留审计。

测试：未登录/非管理员拒绝、跨作用域引用、草稿版本不可绑定、归档不能新增绑定、并发 409、正文超限、无效 UTF-8、无精确模型范围、预览零网络请求。

验收：管理 API 可完成创建→编辑→发布→绑定→回滚；每次写入有对应管理审计。

## 5. M3：策略解析和网关注入

拟修改范围：新增 resolver/adapter service；在 M0 确定的 handler、调度器和四条 gateway 路径接入。

任务：

1. 保留原始 body 和配置一致快照，不持有数据库事务等待网络。
2. 首个账号确定后、首次发送前冻结 enabled/version/profile 语义。
3. 把策略兼容性接入后续账号选择；跨组 fallback 不得绕开原授权检查。
4. Chat 添加独立 system 消息；Responses 追加 instructions，保留客户端字段。
5. 每次尝试重建 body，保证只注入一次。
6. 最终 body 校验后计算签名与内容相关缓存标识。
7. 明确处理配置不可读、无兼容账号、未支持历史引用和协议；不得悄悄不注入。
8. 保持原有 SSE、取消、usage 和工具调用行为。
9. 配置默认关闭；关闭时不引入模板数据库依赖。

核心测试必须使用本地捕获上游，断言最终发送字节/JSON结构，不能只测适配器返回值：

| 场景 | 断言 |
|---|---|
| 四条支持路径 | 正确字段中出现一次固定版本正文 |
| 已有 system/developer/instructions | 原值和相对顺序保留 |
| tools、tool_calls、多模态内容 | 非目标结构不变 |
| 同账号重试/跨账号重试 | 正文不累积，版本不变化 |
| 不同覆盖版本的候选账号 | 被排除，耗尽时明确错误 |
| 首次选择 disabled | 后续不能突然启用 |
| 绑定更新恰逢重试 | 该请求仍使用冻结策略，新请求读新策略 |
| fallback 到另一组 | 权限与策略兼容均满足才允许 |
| 签名 | 对最终 body 校验成功 |
| SSE 已提交后失败 | 不切账号重播、不重复输出 |
| previous_response_id / conversation | 启用时明确不支持，关闭时无回归 |

验收：所有支持 profile 都有真实发送层契约证据；不支持路径的后台配置和运行错误一致。

## 6. M4：管理界面与运行观测

拟修改范围：前端管理 API 客户端、类型、页面/组件、路由和导航、多语言，以及后端请求事件写入与查询。

任务：

- 模板列表与详情，草稿编辑、版本 diff 和固定版本发布。
- 分组开关/固定版本选择，账号关系继承、禁用和覆盖。
- 展示适用模型、账号兼容性、发布状态与独立验证状态。
- 结构预览显示注入位置、原始字段保留情况；不宣称可预知模型效果。
- 请求详情展示策略来源、版本 hash、各次尝试与跳过原因。
- 记录失败请求策略事件；异步日志写入失败不引发上游重试。
- 提供回滚至旧版本入口及并发更新冲突提示。

实施 Vue 文件前加载当时可用的 Vue 开发技能；采用现有设计系统、Composition API、TypeScript 和 i18n 约定。

测试：版本选择不会默认 latest；覆盖在分组关闭时显示不生效；409 不吞掉用户编辑；敏感正文不出现在普通列表；失败请求可追溯；语言 key 完整。

验收：管理员无需手写 JSON 即可完成模板发布与分组绑定；请求记录能解释实际是否应用。

## 7. M5：有限预算 A/B 和评估记录

任务：

- 实现管理员显式创建的评估任务、状态查询和取消。
- 固定版本、模型、同一账号、参数、用例摘要和最大请求数；默认一对、无自动重试。
- 基线只关闭本次模板，保留其他现有兼容处理。
- 记录实际 usage、延迟、失败、响应和人工判定理由。
- 多轮两组使用相同追问，分别携带各自模型回复。
- 保存证据范围与局限，不能从关键词推断“成功破甲”。
- 已有候选仅提供手动草稿导入，不自动发布或绑定。
- 设置响应和元数据保留期、清理任务与管理员访问限制。

任务执行采用持久任务状态 queued/running/completed/failed/cancelled；worker 重启后，将不确定是否已发送的请求标记 indeterminate，不自动补发以免重复费用。幂等创建只去重任务创建，不声称上游生成调用具备 exactly-once 保证。

测试：超时、取消、worker 重启、请求预算耗尽、错误计入样本、无跨渠道补发、脱敏和保留期清理。

验收：完成无害的格式遵循与普通文本任务对照；可以区分注入正确、行为差异与无法判定。

## 8. M6：集成验收与灰度

按以下顺序执行并保存命令、commit、退出码与摘要：

1. 运行受影响 Go 包的单元/契约测试。
2. 在隔离 PostgreSQL 环境运行迁移、约束与并发集成测试；按仓库实际 build tags/环境参数执行。
3. 执行前端 pnpm run typecheck、pnpm run test:run、pnpm run lint:check、pnpm run build。不可用环境需明确记录，不能记作通过。
4. 使用本地模拟上游跑四路径、重试、SSE、签名、关闭功能回归矩阵。
5. 对新增配置查询和注入做本地性能基准；记录 p50/p95 与新增数据库查询数，核实无每请求外部网络访问。
6. 部署到测试环境，功能默认关闭，验证原请求行为。
7. 仅在测试分组绑定一个固定版本，完成显式小预算文本调用。
8. 演练切回旧版、关闭分组、关闭部署开关和程序回退。

不要将上面的命令当作已经执行；最终以仓库实际测试脚本和环境为准。

验收报告包含：已支持 profile、排除路径、全部测试证据、实际样本局限、迁移说明、配置操作、回滚记录与未解决问题。

## 9. 完成定义

- 管理员能创建、发布、绑定、覆盖、禁用和回滚固定版本。
- 发布后不可变，更新不会影响旧绑定。
- 所有支持路径最终出站包含一次正确正文，客户端指令与工具结构保留。
- 单个逻辑请求的重试不会改变模板策略。
- 不支持、配置失败和跳过均可解释，不存在显示启用但静默忽略。
- 图片链路未纳入；其他已有注入功能没有被隐式替换。
- 发布、结构验证、行为评估状态分离。
- 关闭功能时现有请求无功能回归。
- 生产部署作为后续操作单独处理，本计划不等于已部署。

## 10. 估算与风险

M0 后再给出可靠工期；当前主要工作量在协议/调度一致性而非表单。若任一路径无法满足最终 body 和签名顺序，优先补齐该路径结构，不能靠放宽失败策略掩盖问题。

最大风险：现有平台兼容分支多、账号覆盖缩小 failover 池、增加模板影响 token/缓存成本、服务端历史累积、日志泄露正文。分别通过 profile 门控、绑定预检、真实 usage、历史模式暂不开放、最小审计字段处理。

设计发生变更时同时更新详细设计、API 契约和对应测试，不把实现中临时选择留成未记录行为。
